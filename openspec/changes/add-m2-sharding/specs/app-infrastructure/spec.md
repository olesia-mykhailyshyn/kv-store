# Spec Delta

## Purpose

Розгортання застосунку kv-сховища в AWS-пісочниці лише з IaC: де стоять сервери, хто з ким може говорити по мережі, як код потрапляє на сервери без інтернету, і як не вийти за ліміти пісочниці.

## ADDED Requirements

### Requirement: Застосунок описаний лише в IaC
Усі ресурси застосунку (сервери, диски, security groups, бакет для коду) SHALL створюватися з CloudFormation-шаблонів у репозиторії, в стеках окремо від мережі. Мережеві ID MUST братися з експортів `kv-network`, а не копіюватися вручну.

#### Scenario: Підняти з нуля
- **WHEN** на початку сесії мережу і стеки застосунку розгортаються з шаблонів
- **THEN** сховище працює без ручних кроків у консолі

### Requirement: Розміщення компонентів
Coordinator і шарди SHALL працювати в приватних підмережах без публічних IP; два шарди MUST бути в різних AZ. Клієнт (YCSB, `curl`) SHALL працювати в публічній підмережі.

#### Scenario: Перевірка розміщення
- **WHEN** читаємо опис серверів стека застосунку
- **THEN** coordinator і шарди в приватних підмережах без публічної IP, шарди в різних AZ, клієнт у публічній підмережі

### Requirement: Мінімальний мережевий доступ
Security groups MUST дозволяти лише: клієнт → coordinator (порт API); coordinator → шарди (порт API шарда); шарди → coordinator (реєстрація); SSH до клієнта лише з вказаного діапазону адрес. Будь-який інший вхідний трафік MUST бути заборонений.

#### Scenario: Клієнт не дістає шард напряму
- **WHEN** клієнт звертається на IP і порт шарда
- **THEN** з'єднання не встановлюється

#### Scenario: Інтернет не дістає coordinator
- **WHEN** переглядаємо правила security group coordinator
- **THEN** нема правил з джерелом `0.0.0.0/0`

### Requirement: Код доставляється без інтернету
Сервери в приватних підмережах SHALL отримувати код застосунку з S3-бакета через S3 Gateway Endpoint, без NAT і без доступу в інтернет. Бакет MUST існувати і містити код до створення серверів.

#### Scenario: Старт сервера
- **WHEN** coordinator або шард стартує в приватній підмережі
- **THEN** він завантажує архів коду потрібної версії з S3 і запускає сервіс

### Requirement: Межі пісочниці і бюджету
Стеки M2 MUST використовувати не більше 4 EC2 (ліміт пісочниці — 9), лише типи `t3.micro`/`t3.small`, і MUST NOT містити погодинно платних мережевих ресурсів (NAT Gateway, Interface VPC Endpoint, ALB).

#### Scenario: Склад стеків
- **WHEN** переглядаємо ресурси стеків M2
- **THEN** EC2 не більше 4, типи лише `t3.micro`/`t3.small`, нема NAT Gateway, Interface Endpoint і Load Balancer

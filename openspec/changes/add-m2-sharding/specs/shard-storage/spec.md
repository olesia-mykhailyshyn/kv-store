# Spec Delta

## Purpose

Як шард зберігає свої записи: підтверджений запис не губиться при перезапуску процесу, а стан після перезапуску такий самий, як до нього.

## ADDED Requirements

### Requirement: Підтверджений запис довговічний
Шард MUST підтверджувати запис або видалення лише після того, як зміну дописано в журнал на диску й примусово збережено (fsync). Журнал MUST бути append-only: наявні рядки не переписуються.

#### Scenario: Падіння після підтвердження
- **WHEN** шард відповів `201` на запис, і одразу після цього процес шарда примусово завершено (`kill -9`)
- **THEN** після перезапуску шарда запис читається

### Requirement: Відновлення стану після перезапуску
Після перезапуску шард SHALL відновлювати стан, програючи журнал від початку. Стан після відновлення MUST збігатися зі станом до перезапуску, включно з перезаписами й видаленнями.

#### Scenario: Перезапис і видалення переживають перезапуск
- **WHEN** у шард записано `A=1`, потім `A=2`, `B=1`, потім `B` видалено, і шард перезапущено
- **THEN** `A` читається зі значенням `2`, а `B` — `404`

#### Scenario: Пошкоджений останній рядок
- **WHEN** останній рядок журналу обрізаний (процес упав посеред дописування)
- **THEN** шард стартує, відкидає лише цей рядок і відновлює всі попередні

### Requirement: Записи одного partition key впорядковані за sort key
Шард SHALL повертати записи одного `(table, partition key)` у порядку зростання sort key (порівняння рядків), з урахуванням меж діапазону.

#### Scenario: Порядок незалежний від порядку запису
- **WHEN** записи з sort key `2026-11-05`, `2026-10-30`, `2026-11-01` записано саме в такому порядку
- **THEN** Query повертає їх як `2026-10-30`, `2026-11-01`, `2026-11-05`

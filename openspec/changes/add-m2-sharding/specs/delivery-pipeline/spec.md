# Spec Delta

## Purpose

Конвеєр доставки змін: кожна зміна автоматично перевіряється, а інфраструктура й застосунок деплояться одним запуском з перевіркою, що сховище справді працює.

## ADDED Requirements

### Requirement: Перевірки на кожну зміну
На кожен push і pull request SHALL автоматично запускатися CI без доступу до AWS: тести, лінтер шаблонів CloudFormation, валідація `api/openapi.yaml`. Будь-яка невдала перевірка MUST робити запуск червоним.

#### Scenario: Зламаний тест
- **WHEN** push містить зміну, що ламає тест кільця
- **THEN** CI-запуск завершується з помилкою

#### Scenario: CI без лаби
- **WHEN** сесія пісочниці не запущена
- **THEN** CI все одно виконується і проходить для коректного коду

### Requirement: Деплой інфраструктури й застосунку одним запуском
Запуск CD (вручну, кнопкою) SHALL послідовно: розгорнути мережу, опублікувати код у S3, розгорнути стеки застосунку з цією версією коду. Повторний запуск без змін MUST NOT видаляти або перестворювати мережу.

#### Scenario: Перший деплой у сесії
- **WHEN** на початку сесії (акаунт порожній) запущено CD
- **THEN** мережа і застосунок створені, сховище відповідає

#### Scenario: Повторний запуск
- **WHEN** CD запущено вдруге без змін у шаблонах мережі
- **THEN** стек мережі не змінюється

### Requirement: Smoke test після деплою
CD SHALL після деплою перевірити працездатність зсередини VPC (створити таблицю, записати, прочитати, видалити тестовий запис). Невдала перевірка MUST робити запуск CD червоним.

#### Scenario: Сервіс не стартував
- **WHEN** стек створено, але процес coordinator не працює
- **THEN** smoke test падає, і запуск CD червоний

### Requirement: Ключі доступу не потрапляють у репозиторій
Ключі сесії пісочниці MUST зберігатися лише в GitHub Secrets і MUST NOT з'являтися в коді, у логах pipeline чи в історії git.

#### Scenario: Перевірка логів
- **WHEN** переглядаємо лог запуску CD
- **THEN** значення ключів замасковані

# Spec Delta

## Purpose

Мережа, у якій живуть усі ресурси kv-сховища: ізольована VPC з публічними підмережами для того, що має бути доступне з інтернету, і приватними підмережами для внутрішніх компонентів (шарди, репліки), повністю описана в IaC.

## ADDED Requirements

### Requirement: Мережа описана лише в IaC
Усі мережеві ресурси (VPC, підмережі, Internet Gateway, таблиці маршрутів) SHALL створюватися з CloudFormation-шаблону в репозиторії. Ручні зміни в консолі MUST NOT бути частиною робочого стану мережі.

#### Scenario: Ресурси належать стеку
- **WHEN** мережевий стек розгорнуто
- **THEN** кожна VPC, підмережа, IGW і route table цієї мережі є ресурсом цього CloudFormation-стека

#### Scenario: Ручну зміну видно
- **WHEN** хтось у консолі змінив властивість ресурсу стека (наприклад, теги VPC або `MapPublicIpOnLaunch` підмережі)
- **THEN** drift detection стека показує цей ресурс як `MODIFIED`

### Requirement: Публічні підмережі мають вихід в інтернет
Кожна публічна підмережа SHALL мати в своїй route table маршрут `0.0.0.0/0` на Internet Gateway, приєднаний до VPC.

#### Scenario: Маршрут до IGW
- **WHEN** читаємо route table, прив'язану до публічної підмережі
- **THEN** у ній є маршрут `0.0.0.0/0` з ціллю `igw-…` цієї VPC

### Requirement: Приватні підмережі лише для внутрішнього доступу
Приватні підмережі MUST NOT мати маршруту в інтернет: у їхніх route table немає маршруту `0.0.0.0/0` на IGW. Ресурс у приватній підмережі MUST NOT бути досяжним з інтернету.

#### Scenario: Немає маршруту назовні
- **WHEN** читаємо route table, прив'язану до приватної підмережі
- **THEN** у ній є лише маршрут `local` для CIDR VPC і немає маршруту `0.0.0.0/0` на `igw-…`

#### Scenario: Явна прив'язка до route table
- **WHEN** перевіряємо прив'язки route table у VPC
- **THEN** кожна приватна підмережа явно прив'язана до приватної route table, а main route table VPC не має маршруту на IGW

### Requirement: Зв'язок усередині VPC
Ресурси в публічних і приватних підмережах однієї VPC SHALL мати маршрут одне до одного через маршрут `local`.

#### Scenario: Публічна підмережа бачить приватну
- **WHEN** ресурс у публічній підмережі звертається на приватну IP-адресу в приватній підмережі
- **THEN** route table спрямовує пакет маршрутом `local`, без IGW

### Requirement: Мережа не має погодинно платних ресурсів
Мережевий стек M1 MUST NOT містити ресурсів, які тарифікуються погодинно (NAT Gateway, Interface VPC Endpoint тощо), щоб уміститися в бюджет $20. Додати такий ресурс можна лише після окремого ADR з розрахунком вартості.

#### Scenario: Перевірка складу стека
- **WHEN** переглядаємо список ресурсів мережевого стека
- **THEN** у ньому немає `AWS::EC2::NatGateway` і `AWS::EC2::VPCEndpoint` типу `Interface`

### Requirement: Ідентифікатори мережі доступні наступним майлстоунам
Мережа SHALL робити доступними ідентифікатори VPC, публічних і приватних підмереж, щоб ресурси M2+ могли розгортатися в неї без ручного копіювання ID.

#### Scenario: ID видно після деплою
- **WHEN** мережевий стек розгорнуто
- **THEN** ID VPC і всіх підмереж можна отримати з виходів (Outputs) стека

### Requirement: Відтворюваність з IaC
Мережу SHALL можна повністю знести і підняти знову лише з шаблону в репозиторії, без ручних кроків у консолі.

#### Scenario: Знести й підняти
- **WHEN** мережевий стек видалено, а потім розгорнуто знову з того самого шаблону
- **THEN** стек досягає `CREATE_COMPLETE`, і нова мережа задовольняє всі вимоги цієї специфікації

#### Scenario: Після видалення нічого не лишається
- **WHEN** мережевий стек видалено
- **THEN** у регіоні не лишається VPC, підмереж, IGW чи route table, створених цим стеком

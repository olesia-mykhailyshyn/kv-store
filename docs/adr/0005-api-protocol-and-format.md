# ADR-005: API — REST + JSON, контракт в OpenAPI

- **Status:** Accepted
- **Date:** 2026-11-05
- **Milestone:** M2 (обов'язковий ADR «API protocol and format»)

## Context

M2, завдання 1: описати API для реєстрації визначення таблиці та CRUD над записами (EXISTS, CREATE, READ, DELETE). Опційно — складений ключ partition key + sort key; ми його робимо (ADR-007).

Хто говорить з API:
- **клієнти сховища:** YCSB (M2, M3, M5), `curl` на демо, MCP-сервер (M4);
- **шарди:** реєструються в coordinator (`POST /shards/register`);
- **coordinator:** пересилає запити на шарди (внутрішнє API).

Обмеження:
- **API Gateway у пісочниці нема.** Точка входу — приватна IP coordinator (ADR-009); у майбутньому можливий ALB.
- **Coordinator і шарди на Python, лише стандартна бібліотека** (ADR-008). gRPC або GraphQL потребували б сторонніх пакетів на сервері, а інтернету в приватних підмережах нема.
- **Специфікація пишеться до коду** (правило курсу).

## Options

### A) REST + JSON, контракт в OpenAPI
- ➕ Перевіряється `curl` без спеціальних інструментів, легко показати на демо.
- ➕ HTTP-сервер і JSON є в стандартній бібліотеці Python (`http.server`, `json`).
- ➕ Працює з будь-якою точкою входу (пряма IP, ALB). Для YCSB є REST-підхід (перевірити binding).
- ➕ OpenAPI — стандарт: з нього генерується документація, ним валідуються запити в тестах.
- ➖ JSON поверх HTTP/1.1 повільніший і «товстіший», ніж бінарний протокол.

### B) gRPC + protobuf
- ➕ Бінарний, швидкий, строгі типи; streaming.
- ➖ Потрібні `grpcio` і генерація коду — сторонні пакети на сервері.
- ➖ `curl` не підходить, потрібен `grpcurl`; важче показати.
- ➖ Перевага в швидкості не проявиться: на `t3.micro` вузьке місце — CPU й мережа, а не формат.

### C) GraphQL
- ➖ Створений для складних зв'язаних даних, де клієнт обирає поля. У KV лише «дай / поклади за ключем».
- ➖ Сторонні бібліотеки, складніший сервер, кешування й throttling (бонус у M3) важчі.

## Decision

**Обираємо A — REST + JSON, контракт `api/openapi.yaml` (OpenAPI 3.1).**

**Публічне API (клієнт → coordinator):**

| Операція | Метод і адреса | Успіх | Помилки |
|---|---|---|---|
| Створити таблицю | `POST /tables` `{"name","partitionKey","sortKey?"}` | `201` | `400`, `409` (вже є) |
| Опис таблиці | `GET /tables/{table}` | `200` | `404` |
| CREATE (put) | `PUT /tables/{table}/items` `{<pk>: "...", <sk>: "...", "value": {...}}` | `201` | `400`, `404` (таблиці нема), `503` (шард недоступний) |
| READ | `GET /tables/{table}/items/{pk}[/{sk}]` | `200` + запис | `404` |
| EXISTS | `HEAD /tables/{table}/items/{pk}[/{sk}]` | `200` без тіла | `404` |
| DELETE | `DELETE /tables/{table}/items/{pk}[/{sk}]` | `204` | `404` |
| Query за PK (діапазон SK) | `GET /tables/{table}/items/{pk}?skFrom=&skTo=` | `200` + список, впорядкований за SK | `400`, `404` |

`{sk}` в адресі обов'язковий для таблиць зі sort key і заборонений для таблиць без нього (`400`). Ключі в адресі — URL-encoded.

**Службове API:**
- `POST /shards/register` `{"id","url"}` — шард → coordinator (ADR-009);
- `GET /health` — для smoke test і M5;
- coordinator → шард: ті самі операції над записами з префіксом `/internal/…`, описані в тій самій специфікації окремим тегом `internal`.

**Помилки:** завжди JSON `{"error": "<код>", "message": "<текст>"}`.

**Ключі й значення:** PK і SK — рядки; `value` — будь-який JSON-об'єкт. Обмеження розміру — у специфікації.

## Чому (докладно)

1. **Нуль залежностей на сервері.** REST + JSON — стандартна бібліотека; B і C вимагають пакетів, яких без інтернету на сервер не поставити.
2. **Демонстрованість.** На захисті будь-яку операцію можна показати одним `curl`.
3. **Контракт до коду.** `openapi.yaml` — заморожений контракт: тести і CI (ADR-010) перевіряють код на відповідність йому.
4. **Швидкість B не важлива для M2.** YCSB порівнює M2 з M3/M5 на тому самому протоколі; важить різниця, а не абсолютні числа.
5. **HTTP-коди = семантика KV.** `404` = нема ключа, `HEAD` = EXISTS без тіла, `409` = таблиця вже є — нічого не треба вигадувати.

## Consequences

**Отримуємо:**
- простий, перевірюваний `curl`-ом API;
- один формат для клієнтів, шардів і майбутнього MCP-сервера (M4);
- основу для throttling (`429`) і кешу (бонуси, M3).

**Платимо:**
- JSON і HTTP/1.1 — накладні витрати на кожен запит (видно в latency YCSB);
- валідація за OpenAPI відбувається в тестах, а не на сервері (на сервері — ручні перевірки в коді).

**Що відкинули і чому:**
- **gRPC** — сторонні пакети, важче показати, перевага в швидкості тут не проявиться.
- **GraphQL** — не підходить для доступу за ключем.

## Де це в коді

- `api/openapi.yaml` — контракт (пишеться першим).
- Coordinator: по обробнику на кожну адресу специфікації.
